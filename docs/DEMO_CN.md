# 五分钟课堂演示

## 第一分钟：解释问题

“同学们的方案主要通过新进程或角色配置隔离。我进一步研究：隔离之后，Agent 怎么安全地共享必要数据并交付成果？我的方案用容器封闭执行环境，用宿主 Broker 管理明确的信息通道。”

展示 README 的隔离范围；指出 Docker 共享内核，避免宣称绝对安全。

## 第二分钟：检查与运行

预先构建镜像，然后运行：

```powershell
python capsule/cli.py doctor
python capsule/cli.py demo
```

解释这里用了确定性模型替身，以便现场无需联网、不会产生模型费用；Agent 循环、三个隔离容器和结果交付真实运行。

## 第三分钟：展示成果

打开输出目录中的 `result.json` 和 `artifacts/.../analysis.json`。数据 10、20、30 的均值为 20。reviewer 从新上下文重算并比较结果。展示文件 SHA-256 与摘要元数据。

指出原始 samples.csv 没有被修改，也没有挂载进任何容器。

## 第四分钟：证明边界

```powershell
$env:CAPSULE_DOCKER_TESTS="1"
python -m unittest discover -s tests -v
```

展示拒绝未授权读取、reviewer 写入、路径穿越；然后展示容器无网络、无宿主环境 canary、独立临时目录。只有 PASS 才说通过，SKIP 不能说通过。

## 第五分钟：真实模型与局限

用已准备好的 Ollama 模型执行 README 中的真实 `run` 示例。模型可能输出格式错误或得出错误结论，诚实展示失败记录；权限拒绝不依赖模型是否听话。

## 常见答辩问题

**主 Agent 在哪里？** Pi 命令是入口；真正主 Agent 在单独容器中，每轮请求模型，唯一工具是 delegate。

**子 Agent 为什么拿不到主历史？** Broker 新建任务包，代码中没有复制父 messages；子 Agent 自己创建新消息数组。

**为什么不用现成 subagent 包？** 作业重点是自己实现信息边界和成果交付，而不是组合现成角色配置。

**容器断网怎么调用模型？** 容器经 stdin/stdout 发推理请求，宿主 Broker 调用本机 Ollama；Agent 不接触地址选择和认证。

**为什么既有 analyst 又有 reviewer？是否与同学重复？** 角色名称不是原创点；核心是独立授权的数据副本、无凭据/网络容器和可检查的成果通道。reviewer 是验证该机制的示例。

**如何证明没有任何泄漏？** 不能证明所有语义信息流不存在。能证明实现中的通道、拒绝条件与测试覆盖；主 Agent 显式写进任务的信息会被发送。

**为什么不能直接写项目？** 本版只交付候选成果，原始工作区不进入执行环境。扩大到直接写项目需要新增提交授权、冲突与回滚设计。

**是否全部测试过？** 按 docs/VALIDATION.md 报告，分开说明本地进程、Docker 和真实模型验证。
